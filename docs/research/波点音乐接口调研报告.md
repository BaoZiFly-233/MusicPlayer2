# 波点音乐（Bodian）第三方接口调研报告

> 调研时间：2026-09-12 ｜ 方法：`gh` 读远端仓库源码 + 实测 HTTP 端点 + web 搜索交叉验证
> 结论先行：**波点音乐没有任何字节跳动接口，它是酷我（Tingtin/腾讯音乐）的产品，接口完全走 `*.kuwo.cn`。不需要 `X-Gorgon`/`X-Argus`。但匿名拿不到付费歌曲的完整播放地址。**

---

## 0. 最重要的纠正

任务描述里「波点音乐 = 字节跳动旗下 / 与抖音同源」是**错的**。

| 证据 | 内容 |
|---|---|
| 百度百科 | 波点音乐是**北京酷我科技有限公司**开发，2020-12-14 上线，隶属**腾讯音乐娱乐集团（TME）** |
| 全部接口域名 | `bd-api.kuwo.cn`、`bodianimgcdn.kuwo.cn`、`bd-er.kuwo.cn`、`search.kuwo.cn`、`antiserver.kuwo.cn` —— 全是 `kuwo.cn` |
| App 标识 | HTTP 头 `user-agent: bodian/29 CFNetwork/1240.0.4`；`ver: 3.2.3`；`channel: appstore` |
| 接口字段 | 返回体里直接带 `bodianAlbum`、`bodianPayAlbum`、`bodianPayAlbumOffline` |

**工程含义**：不存在「字节签名」这一关。波点接口的鉴权是**弱头校验**，不是签名。这比原本预期的简单一个数量级。

## 2. 请求参数与鉴权

### 2.1 必填 query 参数

只有三个：`uid`、`token`、以及具体业务参数（`keyword`/`pn`/`rn`/`id`）。

- `uid=-1` + `token=`（空串）→ **匿名模式**，搜索/详情/歌词/推荐全部可用。
- 无需 `aid` / `device_platform` / `version_code` / `iid` / `device_id` / `s_param`。
- **不需要 `X-Gorgon` / `X-Argus` / `X-Khronos`**，也不需要任何 MD5/RSA 签名。

### 2.2 关键：`audioUrl` 认头不认签名（本次调研最有价值的发现）

`/api/service/music/audioUrl/{id}` 的结果**完全取决于请求头**：

| 头组合 | 结果 |
|---|---|
| 无任何自定义头 | ❌ HTTP **402** |
| 只加 `Referer: https://www.kuwo.cn/` | ❌ HTTP **402** |
| 波点 **iOS** 头（`plat=ip` / `channel=appstore` / `brand=iPhone13,1` / `ver=3.2.3`） | ❌ `code 20012 歌曲已下线` |
| 波点 **iOS** 头 + `appuid` | ❌ `code 20012 歌曲已下线` |
| 波点 **Android** 头（见下） | ✅ `code 200`，返回完整 `audioUrl` |

**可用的 Android 头（实测通过）**：

```
plat: ar
channel: huawei
brand: huawei mate40
devid: da1947619a05c9ea
ver: 1.1.9
appuid: 123849114429
api-ver: application/json
net: mobile
content-length: 0
user-agent: Dart/2.10 (dart:io)
```

失败时的两套错误语义要区分清楚：

- `code 20012 歌曲已下线` → 头不对 / 该曲在波点无版权
- `code 20018 没有解锁付费歌曲` → **头对了，是歌曲本身要会员**

`20018` 是有用的正面信号，说明你的伪装头已经生效。

### 2.3 `audioUrl` 正常响应形状

```json
{
  "code": 200,
  "data": {
    "audioUrl":      "http://bd-lw.kuwo.cn/<32位hex>/<8位hex>/resource/30106/trackmedia/M800003V7OMc0D2QCg.mp3?from=bodian",
    "audioHttpsUrl": "https://bd-lw.kuwo.cn/...（同一条，https）",
    "format": "mp3",
    "duration": 236,
    "bitrate": 320,
    "size": "8.5Mb",
    "respCode": 200,
    "p2pAudioSourceId": "…"
  }
}
```

服务端会**自动给该曲可用的最高音质**（实测拿到过 128 / 320 两档，`ff` 无损档匿名不给）。

### 2.4 绕开官方接口的公开音源解析服务（都实测可用）

如果不想自己维护伪装头，可以直接用第三方聚合，代价是可控性和稳定性。

| 服务 | 端点 | 实测 |
|---|---|---|
| 小尘 API | `https://api.xcvts.cn/api/music/bdyy?msg=<kw>&sc=10&type=json`（列表）<br>`https://api.xcvts.cn/api/music/bdyy?msg=<kw>&n=1&type=json`（详情，返回 `play_url` + `lrc`） | ✅ 已验证。详情返回 `?from=bodian` 直链，本次实测拿到 **真 FLAC（55 MB，魔数 `fLaC`）** |
| 星之阁 API | `https://api.xingzhige.com/API/Kuwo_BD_new/?name=<kw>`（列表）<br>`...&name=<kw>&n=1`（详情） | ✅ 已验证。返回体带 `raw` 字段，**直接暴露它背后就是调 `bd-api` 的 `audioUrl`** |
| `a.aa.cab/bd.music`（VZService 用的） | `https://a.aa.cab/bd.music?msg=<kw>&num=10` | ❌ 本次 TLS 握手失败 |

星之阁返回的 `raw` 字段（等于把官方响应原样转发）：

```json
{
  "audioUrl": "http://bd-er.kuwo.cn/<hex>/<hex>/resource/30106/trackmedia/M500000bYDlc2XxKLs.mp3?from=bodian",
  "format": "mp3", "duration": 269, "bitrate": 128, "size": "4.12Mb",
  "respCode": 200, "p2pAudioSourceId": "…",
  "audioHttpsUrl": "https://bd-er.kuwo.cn/…"
}
```

**反过来推**：说明这些聚合服务持有能过 `audioUrl` 的请求配置（很可能是带会员的 `uid`/`token` 或更完整的头），所以它们能拿到无损和付费曲。这也是它们的护城河，也是它们的单点故障。

## 4. 播放地址：是明文，但有三个坑

### 4.1 明文 ✅

`audioUrl` 和 `anti.s` 都直接返回**明文 http/https 直链**，无加密、无二次换取。

### 4.2 防盗链：**没有** ✅（实测）

对同一 CDN 直链：

| 请求头 | 结果 |
|---|---|
| 完全不带 Referer / UA | HTTP 200，`Content-Type: audio/mpeg` |
| 伪装波点 iOS UA + `h5app.kuwo.cn` Referer | HTTP 200 |
| **故意错误** Referer（`example.com`）+ `curl/8` UA | HTTP 200 |
| 去掉 `?from=bodian` | HTTP 200 |
| `?from=whatever` | HTTP 200 |

**结论：CDN 不校验 Referer/UA，`from=bodian` 是无意义标记。第三方播放器可以直接播。**

`Accept-Ranges: bytes` 存在，支持拖动进度条。

### 4.3 时效性 ⚠️

URL 结构：`https://bd-lw.kuwo.cn/<32位hex签名>/<8位hex>/resource/30106/trackmedia/M800003V7OMc0D2QCg.mp3`

**第 2 段 hex 解出来就是 Unix 时间戳**，实测验证：

```
token = 6aa56d83 -> 1789226371，而当时 UTC = 1789226371   （相差 0 秒）
token = 6aa56d76 -> 1789226358，当时 UTC = 1789226358      （相差 0 秒）
```

所以 URL 是**带签发时间戳的签名链接，会过期**。

- 实测：签发后 **61 秒仍可用**；签发后 **229 秒仍可用**。
- 未测出确切过期点（需要长时间观察）。参考工程量级：同项目 [chaser114](https://github.com/chaser114/taemspeak3-bodian) 的 `KuwoMusicPlugin.cs` 里写死 `AudioUrlLifetime = TimeSpan.FromHours(12)`，**这是作者的经验值，不是官方文档**，标记为推测。

**工程做法**：拿到 URL 后立刻用；播放前若距签发超过安全窗口（建议 ≤30 分钟）就重新解析；缓存里只存 `id`，不存 URL。

## 5. 是否需要登录

### 5.1 匿名能做什么 ✅

搜索、联想、热搜、歌曲详情、歌词（base64 LRC）、推荐流、榜单、分类歌曲、用户公开信息 —— **全部匿名可用**，只要 `uid=-1&token=`。

### 5.2 匿名播放：**只能拿到免费曲，付费曲拿不到** ❌ ← 这是最硬的结论

对同一批 29 首「热门」搜索结果做全量对比测试：

| 路径 | 匿名拿到完整播放地址 |
|---|---|
| `bd-api .../audioUrl/{id}` | **1 / 29** |
| `antiserver.kuwo.cn/anti.s` | 29 / 29 返回链接，**但 28 个是同一个占位试听文件** |

#### `anti.s` 的关键陷阱（实测证据）

请求 5 首不同的付费歌，返回的文件路径**完全相同**：

```
rid=MUSIC_228908   (周杰伦-晴天)          -> .../nf/resource/n1/69/32/588957081.mp3
rid=MUSIC_198554068(孤勇者-陈奕迅)        -> .../nf/resource/n1/69/32/588957081.mp3
rid=MUSIC_193290598(如愿-王菲)            -> .../nf/resource/n1/69/32/588957081.mp3
rid=MUSIC_209404086(渐暖-时代少年团)      -> .../nf/resource/n1/69/32/588957081.mp3
rid=MUSIC_207699170(雪龙吟-张杰)          -> .../nf/resource/n1/69/32/588957081.mp3
```

该文件 `Content-Length = 181521` 字节，`Content-Type: audio/mpeg`，@128kbps ≈ **11.3 秒**。

而免费歌各自返回**不同的**真实文件：

```
rid=MUSIC_165923393 -> .../trackmedia/M500003V7OMc0D2QCg.mp3   (CL=3564138，完整)
rid=MUSIC_78932517  -> .../trackmedia/M5000007o3Zx2gYYgk.mp3   (CL=2829338，完整)
rid=MUSIC_180810848 -> .../trackmedia/M5000044TgAD1UkKg4.mp3   (CL=完整)
```

**所以：`anti.s` 对着付费歌返回的不是真链接，是一个统一的 11 秒试听占位文件。** 这是本次调研最重要的负面发现——网上大量教程还在教人用 `anti.s`，但拿到的根本不是完整曲。

#### 官方 API 的错误码对照

```
id=228908    (晴天, 周杰伦)      -> code=20018  msg=没有解锁付费歌曲
id=198554068 (孤勇者, 陈奕迅)    -> code=20018  msg=没有解锁付费歌曲
id=193290598 (如愿, 王菲)        -> code=20018  msg=没有解锁付费歌曲
id=165923393 (哪里都是你, 队长)  -> code=200    bitrate=320  size=8.5Mb  ✅ 完整
```

### 5.3 VIP 曲有办法吗？

- ❌ 用仓库里泄露的固定 token（`137acd3e6d0276020741da2ef35a316b`）→ 仍然是 `20018`。这个 token 只是游客态凭据，不解锁付费。
- ❌ `/api/ucenter/vip/give/popup` 签到接口返回 `code 200` 但 `data:{}`，没有实际 VIP 加成。
- ❌ 无损 `flac` 档：`anti.s?format=flac` 对免费歌也返回 **`refuse request!`**；`bd-api` 匿名不给 `ff` 档。无损只能靠第三方聚合（小尘 API 实测能给真 FLAC）。
- ⚠️ 理论路径：走波点自己的登录流程拿一个**真会员账号**的 `uid` + `token`，再拼 Android 头。**本次未测，标记为推测。** 需要账号，有封号与法律风险。
- ✅ 现成替代：走小尘 API / 星之阁 API。它们能给出付费曲和无损——说明**上游持有会员凭据**。

### 6.2 顺手发现的安全问题

- `BsaLee/bodian_music_api/db.php` **硬编码了 MySQL 明文口令**（`qiandao` / `wh8XKGFxF87yx2sS`）。
- `worker.js` 和 `qyo123oyq` 的 `app_config.dart` 里**硬编码了共享 token** `137acd3e6d0276020741da2ef35a316b`，`qyo123oyq` 的注释直写「固定 Token（从逆向项目获取）」。

**这两个值现在已经公开在 GitHub 上，不应在你的新项目里复用。** 如果非要用，请自己申请/获取独立凭据。

### 6.3 风险提示

1. **违反用户协议**：波点/酷我用户协议禁止未授权抓取和第三方客户端。账号可能被封。
2. **著作权**：音乐版权属唱片公司。绕过会员直接取播放地址，属于规避技术保护措施，在《著作权法》第 53 条下有侵权风险。
3. **《反不正当竞争法》**：以第三方客户端形式提供实质替代服务，风险高于个人学习工具。
4. **接口随时会改**：没有公开文档、没有 SLA、没有兼容承诺。`audioUrl` 的头部校验就是随时可能再变的黑盒。
5. **建议**：定位为**个人学习 / 本地点歌工具**，不要做公开服务、不要做商业化、不要内置到有用户的产品里。真要上线，走正规授权或改用有官方 API 的平台。

## 7. 对比结论：波点 vs 酷狗概念版

| 维度 | **波点音乐** | **酷狗概念版** |
|---|---|---|
| 上游 | 酷我（TME） | 酷狗（TME） |
| 是否需要签名 | ❌ **不需要任何签名** | ✅ **必须**：`signature` = MD5(salt + 参数 + 时间戳 + salt)，32 位 hex |
| 是否需要加密 | ❌ 无 | ✅ RSA 公钥加密 + AES，[KuGouMusicApi/util/crypto.js](https://github.com/MakcRe/KuGouMusicApi) 里两套 RSA 公钥（普通版 / lite 版） |
| 关键坑 | **请求头白名单**：`plat=ar`+`appuid` 才行，`plat=ip` 直接死 | **盐值会轮换**，需要持续跟进 |
| 搜索/歌词 | ✅ 匿名全通 | ⚠️ 部分需要登录态 |
| 匿名播放 | ❌ **付费曲拿不到**（29 首里只成功 1 首） | ❌ 同样需要账号 |
| 现成可用后端 | ⚠️ 无（全是薄壳转发） | ✅ **[MakcRe/KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi)：946 star，549 fork，2026-09-11 还在提交** |
| 现成可用客户端 | ⚠️ 只有半成品 | ✅ **[umr-xiaomai/kgka_Music_hl](https://github.com/umr-xiaomai/kgka_Music_hl)：523 star，2026-09-06 还在提交**（但它自己也指向第三方 API `music.api.hoilai.cn`，签名在服务端） |

### 哪边更容易做出稳定的第三方播放器？

**酷狗概念版明显更容易。** 理由不是技术难度，而是**生态成熟度**：

1. **有人维护签名**。KuGouMusicApi 是活跃项目，酷狗改盐值→几天内有人提 PR 修好。波点这边**没有任何一个在维护的逆向项目**。
2. **有可依赖的服务端**。你可以直接把 KuGouMusicApi 部署起来当后端。波点这边只有第三方公益 API（小尘、星之阁），**随时可能关站**，且不给 SLA。
3. **有活跃的真实用户**。`kgka_Music_hl` 有 15 个 open issue 在报真实播放问题，说明有人在跑、在用、在修。波点全生态 star 数加起来不到 20。
4. **协议复杂度虽然更高，但是"已知的难"**——签名算法已被完整逆向并公开。而波点的难是"未知的难"：头部白名单的规则没人写下来，靠试错，而且平台随时会改。

### 但换一个角度：如果你能接受「只播免费曲」

那**波点反而更简单**——因为**根本不用签名，也不用维护盐值**。整个实现就是：

```
搜索:  GET bd-api.kuwo.cn/api/search/music/list?keyword=…&uid=-1&token=   + Android 头
歌词:  GET bd-api.kuwo.cn/api/service/music/lyric/{id}?uid=-1&token=      + Android 头
播放:  GET bd-api.kuwo.cn/api/service/music/audioUrl/{id}?uid=-1&token=   + Android 头
       → 200 就播；20018 标记为"需会员"；20012 标记为"无版权"
```

不用逆向、不用 Frida、不用跟盐值。代价是**曲库覆盖率极低**（热门榜实测 1/29）。

### 给播放器的落地建议

1. **主力音源选酷狗概念版**（配 `KuGouMusicApi` 自建后端），这是唯一有活人维护的路线。
2. **波点作为补充音源**，只标"免费曲可播"。实现成本几乎为零，可以顺手加上。
3. **绝不要把 `anti.s` 当播放源**。它对付费曲静默返回同一个 11 秒试听文件，你会得到"能播但只响 11 秒"的诡异 bug，而且极难 debug。如果一定要用，请硬编码那个 `588957081.mp3` 的识别逻辑并拒掉它。
4. **缓存只存 `id`**，不存播放 URL。
5. **第三方聚合 API 只做降级兜底**，不要做主力，并把它的失败当成正常路径处理。

## 8. 事实 vs 推测

### ✅ 已验证事实（本次实测 / 源码证据）

- 波点是酷我（TME）产品，不是字节跳动产品
- `bd-api.kuwo.cn` 全部端点匿名可用，无需任何字节签名
- `audioUrl` 认 `plat=ar` + `appuid` 的 Android 头；拒 `plat=ip` 的 iOS 头
- 错误码语义：`20012` = 头不对/已下线，`20018` = 支付墙
- 匿名播放付费曲不可行：`bd-api` 29 首成功 1 首；`anti.s` 对付费曲统一返回 `588957081.mp3`（181521 字节 ≈ 11.3 秒试听）
- CDN 直链无 Referer/UA 防盗链，支持 Range
- URL 里第 2 段 hex = Unix 签发时间戳，链接会过期
- 小尘 API 与小尘/星之阁的聚合端点实测可用，能返回 FLAC
- 星之阁的 `raw` 字段证明它背后调的就是 `bd-api` 的 `audioUrl`
- 六个项目的最后提交时间、star 数、license 状态（见 §3、§6.1）
- 三个仓库无 LICENSE，`qyo123oyq` 自称 MIT 但无 LICENSE 文件

### ⚠️ 推测 / 未验证

- 播放 URL 的**确切过期时长**（只测到 229 秒仍可用；`chaser114` 的 12 小时是作者经验值）
- **带真会员 token 是否能解锁 `20018`**（未登录测试）
- 第三方聚合 API 的**长期稳定性**与是否合规（它们持有会员凭据是合理推断，未证实）
- 星之阁 / 小尘的**限流与封禁策略**
- 波点是否会**随时改头部白名单规则**（无公开文档，无法预判）
